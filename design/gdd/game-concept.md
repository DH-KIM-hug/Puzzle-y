## Elevator Pitch

> 동물 크루 모양 스티커를 판에 끌어다 붙여 가로·세로 줄을 지우는 블록 퍼즐.
> 조각마다 크루 얼굴이 한 칸 있고, 얼굴이 지워지면 그 크루의 능력이 터져 다른 얼굴을
> 건드린다 — 한 조각으로 도미노 연쇄를 설계해 터뜨리는 게임.

## Core Identity

| Aspect | Detail |
| ---- | ---- |
| **Genre** | 캐주얼 퍼즐 — 블록 배치(블록 블래스트류) + 캐릭터 능력 연쇄 + 캐릭터 수집 |
| **Platform** | Mobile (Android 우선, iOS는 이후), 세로 화면 터치 |
| **Target Audience** | 수집형 성취가 + 계획형 퍼즐러 (아래 Player Profile 참조) |
| **Player Count** | Single-player |
| **Session Length** | 스테이지 한 판 2~4분, 한 세션 10~30분 |
| **Monetization** | F2P + 크루 가챠 (게임 내 재화 + 유료 재화). 안전장치: 천장(pity), 중복 → 샤드(shard) 교환, 확률 공개. 유료 결제(IAP)는 T2 소프트런치부터 |
| **Estimated Scope** | MVP: Small (2~3개월, solo, MVP 완성 + 재미 검증까지). 풀 비전: Medium (출시 이후 업데이트로 확장, 별도 재추정) |
| **Comparable Titles** | Block Blast, 1010!, Woodoku (배치 퍼즐) · Disney Emoji Blitz (캐릭터 능력 + 수집) |

## Core Fantasy

**한 조각으로 도미노를 설계하는 쾌감.** 판을 읽고 "여기에 이 조각을 두면 냥이가 할퀴고,
그게 곰곰을 깨우고, 곰곰이 삐약을 터뜨려 알이 마지막 줄을 채운다"를 미리 그린 뒤 — 놓는 순간
스티커들이 들썩이며 차례로 터진다. 내가 모은 크루들이 서로를 깨우며 판을 비우는 장면.

---

## Unique Hook

**"블록 블래스트처럼 끌어다 붙이는데, 조각마다 크루 얼굴이 있어서 지워질 때 능력이 터지고, 그 능력이 다른 얼굴을 건드려 도미노처럼 이어진다."**

- 원형 장르(Block Blast, 1010!, Woodoku)에는 동시 지우기 보너스와 연속 콤보만 있고 **반응형 연쇄가 없다**.
  지워진 칸은 그냥 비고, 한 번 놓으면 결과도 한 번이다.
- 말랑 크루는 한 번 놓은 결과가 **캐릭터 능력으로 여러 단계 번진다**. 연쇄는 운이 아니라 **배치로 설계**한다 —
  드래그 중 연쇄 전체를 미리 보여 주기 때문이다 (프로토타입에서 필수로 확인됨).
- 크루를 모을수록 새 조각 모양 + 새 능력 = 새 연쇄 방식이 생긴다. 수집이 곧 퍼즐 도구.

## Player Experience Analysis (MDA Framework)

### Target Aesthetics (What the player FEELS)

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| **Challenge** (obstacle course, mastery) | 1 | 스테이지 목표 + 제한된 조각 수, 별 1~3개, 긴 연쇄 설계 |
| **Discovery** (exploration, secrets) | 2 | 새 크루 = 새 능력, 크루 조합별 연쇄 패턴 발견 |
| **Sensation** (sensory pleasure) | 3 | 도미노 연쇄 연출 최우선 — 스티커 떼어짐, 순서대로 터지는 컷인, 파티클 |
| **Expression** (self-expression, creativity) | 4 | 3인 팀 조합, 나만의 연쇄 루트 |
| **Fantasy** (make-believe, role-playing) | 5 | 귀여운 크루원 캐릭터성, 최애 애착 |
| **Submission** (relaxation, comfort zone) | 6 | 턴 기반(시간 압박 없음), 귀여운 실패 연출 |
| **Narrative** (drama, story arc) | N/A | 긴 스토리 없음 (안티 기둥) |
| **Fellowship** (social connection) | N/A | 온라인/소셜 기능 없음 |

### Key Dynamics (Emergent player behaviors)
- 조각을 놓기 전에 **연쇄 미리보기를 보며 위치를 이리저리 옮겨 본다** ("연쇄 3 예상!"이 뜨는 자리를 찾는다).
- 줄을 바로 지우지 않고 **얼굴들을 일렬로 모아 두었다가** 한 번에 터뜨린다.
- 막힌 스테이지에서 **팀을 바꿔** 조각 모양과 능력을 바꿔 본다.
- 새 크루를 얻으면 예전에 별 3개를 못 받은 판으로 돌아간다.

### Core Mechanics (Systems we build)
1. **배치 보드** — 8×8, 트레이의 조각 3개를 드래그해 붙이기(회전 없음), 가로·세로 줄이 차면 지우기. 3개를 모두 놓으면 트레이가 새로 채워진다. **실패 조건**: 트레이의 어떤 조각도 놓을 곳이 없거나, 제한 조각 수를 다 쓰고도 목표를 못 이뤘을 때.
2. **크루 얼굴 & 능력** — 팀 크루의 조각마다 얼굴 1칸, 얼굴이 지워지면 그 크루의 능력 발동 (예: 냥이 십자 할퀴기, 곰곰 3×3, 삐약은 자기 가로·세로 줄 중 더 꽉 찬 쪽의 빈칸에 가까운 순으로 알 3개를 채움 — 알은 줄을 완성해 연쇄를 다시 점화할 수 있다). 튜토리얼 스테이지는 스테이지 데이터가 얼굴 없는 조각을 지정할 수 있다.
3. **연쇄 해석기 + 미리보기** — 능력이 다른 얼굴을 지우면 그 얼굴도 발동(도미노). 깊이 상한(프로토타입 시작값 6), 연쇄 단계당 점수 배율 +50%(프로토타입 시작값, `/design-system`에서 확정). 같은 단계에 여러 얼굴이 동시에 지워질 때의 처리 순서는 결정적이어야 한다 (규칙은 연쇄 해석기 GDD에서 정의). **미리보기와 실제 처리가 같은 결정적 규칙 모듈을 공유**해야 예측이 맞는다.
4. **팀 편성 & 수집(가챠)** — 3인 팀 = 트레이에 나오는 조각 풀(모양 + 능력). 재시도 시 직전 팀 유지. 크루는 가챠로 획득: 게임 내 재화(코인/스티커 티켓) + 유료 재화. 천장, 중복 → 샤드(원하는 크루와 교환), 등급별 확률 공개. *(용어: '조각'은 퍼즐 조각만 가리키고, 가챠 중복 보상은 '샤드'로 부른다.)*
5. **스테이지 & 목표** — 제한 조각 수 안에 목표(점수 / 특정 칸 지우기 / 방해물 / 연쇄 N 달성), 별 1~3개.

## Player Motivation Profile

### Primary Psychological Needs Served

| Need | How This Game Satisfies It | Strength |
| ---- | ---- | ---- |
| **Autonomy** (freedom, meaningful choice) | 팀 편성, 조각 위치·순서 선택, 연쇄 루트 설계 | Core |
| **Competence** (mastery, skill growth) | 미리보기로 계획한 연쇄가 그대로 터짐, 별 3개 | Core |
| **Relatedness** (connection, belonging) | 최애 크루원에 대한 애착, 귀여운 반응 | Supporting |

### Player Type Appeal (Bartle Taxonomy)

- [x] **Achievers** (goal completion, collection, progression) — How: 크루 도감 완성, 전 스테이지 별 3개, 최장 연쇄 기록
- [x] **Explorers** (discovery, understanding systems, finding secrets) — How: 크루 조합별 연쇄 패턴 발견
- [ ] **Socializers** (relationships, cooperation, community) — How: 해당 없음 (온라인 없음)
- [ ] **Killers/Competitors** (domination, PvP, leaderboards) — How: 해당 없음 (리더보드는 풀 비전 이후 검토)

### Flow State Design

- **Onboarding curve**: 1-1 얼굴 없는 조각으로 줄 지우기만 → 1-2 얼굴 1개, "얼굴이 지워지면 능력!" 안내와 연쇄 미리보기 첫 등장 → 1-3 두 크루로 첫 2단 연쇄 → 1-5 전후 3인 팀.
- **Difficulty scaling**: 목표 상승 → 조각 수 제한 강화 → 방해물(지워지지 않는 칸, 얼어붙은 얼굴 등) → 특정 능력 조합이 유리한 판.
- **Feedback clarity**: 드래그 중 연쇄 미리보기(지워질 칸, 발동 순서 번호, 예상 알), 터진 뒤 연쇄 단계 컷인, 결과 화면 "최장 연쇄".
- **Recovery from failure**: 놓을 곳이 없으면 스티커북이 "꽉 찼다"는 귀여운 연출 → **원탭 재시작(직전 팀 유지)**. 페널티 없음.

## Core Loop

### Moment-to-Moment (30 seconds)
트레이의 조각 하나를 집어 판 위로 끌고 다니며 연쇄 미리보기를 본다 → 원하는 자리에 붙인다 →
줄이 지워지고 얼굴 능력이 차례로 터진다. 판단(어디 둘까)과 보상(도미노 연출)이 한 동작 안에 있다.
도미노 연출이 일반 줄 지우기보다 **압도적으로** 시원해야 한다 (기둥 1).

### Short-Term (5-15 minutes)
스테이지 하나 = 팀 편성(또는 직전 팀 유지) → 제한 조각 수 안에 목표 달성 → 결과(별 1~3, 코인·티켓) →
재도전 또는 다음 스테이지. "한 판 더"는 별 3개를 아깝게 놓쳤을 때, 그리고 다른 팀으로 더 긴 연쇄가
떠올랐을 때 생긴다.

### Session-Level (30-120 minutes)
10~30분 동안 스테이지 몇 개를 클리어하고 코인·티켓으로 가챠(스티커 팩 개봉)를 돌린다. 새 크루원을
얻는 순간이 자연스러운 정지 지점이자 다음 세션의 동기("이 친구 조각이면 그 판이 풀린다").

### Long-Term Progression
월드맵 스테이지 진행(MVP 10스테이지 → 풀 비전 60스테이지), 크루 도감 채우기(MVP 6명 → 풀 비전 24명+),
전 스테이지 별 3개, 최장 연쇄 기록.

### Retention Hooks
- **Curiosity**: 가챠 픽업 크루원의 조각 모양·능력 힌트, 아직 못 본 연쇄 조합, 천장까지 남은 횟수
- **Investment**: 모은 크루원, 레벨업한 최애, 쌓아둔 샤드
- **Social**: 해당 없음
- **Mastery**: 별 3개 못 받은 스테이지, 최장 연쇄 기록

## Game Pillars

### Pillar 1: 도미노의 손맛 (Domino Payoff)
연쇄가 터지는 순간은 일반 줄 지우기보다 압도적으로 시원해야 한다.

*Design test*: 연출 예산이 부족하면, 일반 줄 지우기·메뉴보다 **얼굴 능력과 연쇄 연출부터** 다듬는다.

### Pillar 2: 크루가 곧 전략 (Crew Is Strategy)
3인 팀이 트레이의 조각 모양과 능력을 정하고, 그것이 클리어 경로를 바꾼다.

*Design test*: (1) 같은 스테이지에서 팀이 다르면 클리어 경로가 눈에 띄게 달라지는가?
(2) A의 능력 결과가 B의 얼굴을 건드려 연쇄를 만들 수 있는가? 새 크루원을 수치 상향과 새 동작 중
하나로 만들어야 하면 → **새 동작(새 모양·새 능력)**. 레벨업 효과는 **최대 +20%로 상한**.

### Pillar 3: 보이는 연쇄 (Readable Chains)
연쇄는 운이 아니라 설계다 — 플레이어는 놓기 전에 결과를 볼 수 있어야 한다. *(프로토타입에서 추가: 얼굴이 스위치라는 규칙은 미리보기 없이는 읽히지 않았다.)*

*Design test*: 새 능력이 미리보기로 정확히 예측 가능한가? 예측 불가능한 랜덤 효과와 예측 가능한 효과 중에서 → **예측 가능한 효과**. 미리보기와 실제 결과가 다르면 버그다.

### Pillar 4: 한 판 더 (One More Round)
짧은 판과 즉각적인 재도전.

*Design test*: 결과 화면에 정보를 더할지, 재시작을 빠르게 할지 → **재시도 시 직전 팀을 유지한 원탭 시작**.

### Pillar 5: 다정한 세계 (Gentle World)
잔인함이 없고, 실패조차 귀엽다.

*Design test*: 패배 연출을 긴장감 있게 할지, 웃기게 할지 → **웃음**.

### Anti-Pillars (What This Game Is NOT)

- **NOT 바닥 없는 가챠**: 천장 없는 뽑기, 확률 비공개, 중복이 쓸모없는 구조는 '다정한 세계'를 해친다. 가챠는 허용하되 천장·샤드 교환·확률 공개를 반드시 둔다.
- **NOT 과금 = 수치 우위**: 희귀 크루원은 '더 센' 수치가 아니라 '더 독특한' 모양·능력으로 차별화한다 (기둥 2). 수치 강화는 +20% 상한 유지.
- **NOT 예측 불가능한 연쇄**: 결과를 미리 볼 수 없는 랜덤 능력은 '보이는 연쇄'를 깨뜨린다.
- **NOT 시간 압박**: 실시간 타이머는 계획 퍼즐을 반사신경 게임으로 바꾼다 (매치-3 블리츠에서 피벗한 이유와도 연결).
- **NOT 스태미나(에너지) 대기 시스템**: 기다리게 만들면 '한 판 더'가 깨진다.
- **NOT 긴 스토리 컷신**: '한 판 더'의 템포와 솔로 일정을 해친다.

## Visual Identity Anchor

**방향: 스티커북 (Sticker Book)** — art-director 제안 3종(젤리 팝 / 스티커북 / 네온 간식) 중 사용자 선택.
퍼즐 바탕이 "스티커를 판에 붙이는" 행위가 되면서 비주얼과 메커닉이 일치하게 됐다.

**비주얼 규칙**: "모든 것은 손으로 오려 붙인 스티커다."

**지원 원칙**
1. **두꺼운 흰 테두리 + 살짝 불규칙한 실루엣** — 모든 크루 조각·UI 버튼은 오려낸 스티커 윤곽을 가진다.
   *Design test*: 새 에셋이 배경 위에서 "붙어 있는 스티커"로 읽히지 않으면 반려. 테두리는 런타임 셰이더가 아니라 **텍스처에 구워 넣는다** (TD 권고, 모바일 성능).
2. **얼굴 칸은 항상 눈에 띈다** — 얼굴은 몸통보다 크고 반짝이는 테두리를 가진다 (프로토타입 교훈). 능력 발동 = 스티커가 들썩 떼어짐 → 효과 → 다시 붙음.
   *Design test*: 판 위에서 얼굴 칸을 1초 안에 모두 찾을 수 있는가?
3. **수집 화면 = 스티커 앨범** — 크루 도감은 앨범 페이지, 미획득은 점선 빈칸 실루엣, 희귀 크루원은 홀로그램 테두리 (홀로 셰이더는 UI에만).
   *Design test*: 수집 UI가 앨범 메타포를 깨면 반려.

**색 철학**: 크라프트지/종이 질감 바탕 위에 중채도 원색(색 = 크루원). 판은 따뜻한 저채도라 조각이 항상
먼저 보인다. 색약 대응을 위해 **색만으로 구분하지 않고** 크루원마다 얼굴 실루엣·조각 모양 차이를 둔다.
터치 대상은 최소 약 64px(1080p 기준).

## Risks and Open Questions

### Design Risks
- 얼굴 = 스위치 규칙이 안 읽히면 그냥 블록 블래스트로 보인다 → 얼굴 강조 + 연쇄 미리보기 필수 (기둥 3).
- 미리보기가 너무 친절하면 퍼즐이 "최고 숫자 뜨는 자리 찾기"로 단순해질 수 있다 → 스테이지 목표·조각 제한으로 트레이드오프를 만든다. 플레이테스트로 확인.
- 트레이 랜덤이 운으로 느껴질 수 있다 → 팀 = 조각 풀로 편차 축소, 스테이지 고정 시드 검토.
- 24명 능력이 서로 겹쳐 개성이 흐려질 위험 → 능력 프리미티브 조합 + "새 동작" 원칙, 그리고 모두 미리보기로 예측 가능해야 함.
- 레벨업이 커지면 조합 전략을 대체 → +20% 상한.
- 유료 가챠가 '크루가 곧 전략'과 충돌(돈 = 강함) → 희귀도는 수치가 아닌 모양·능력 차별화, 클리어 가능성은 일반 등급 크루로도 보장되도록 스테이지 설계.
- 가챠 경제(재화 획득량 vs 천장) 밸런스 실패 시 수집이 지치거나 너무 쉬움 → economy-designer 검토, `/balance-check`.

### Technical Risks
- 미리보기와 실제 처리의 불일치 → 하나의 결정적 규칙 모듈 + 단위 테스트 (같은 판에서 예측 = 결과).
- 연쇄 무한 루프 → 깊이 상한(프로토타입: 6).
- 저가 Android 기기 파티클 성능 → Compatibility 렌더러, 실기기 측정.
- iOS 빌드는 Mac + 연 $99 계정 필요 → Android 우선.
- 고정 Godot 버전이 LLM 지식 이후 버전 → `docs/engine-reference/godot/` 교차 확인.
- 놓치기 쉬운 항목: 노치/세이프 영역, 세이브 버전 관리, Android 오디오 지연.

### Market Risks
- 블록 배치 퍼즐도 클론이 많은 장르 → 차별점은 "얼굴 능력 도미노 + 보이는 연쇄"와 '적당한' 가챠·다정함. 원형 게임의 외형·UI를 따라 하지 않는다.
- 유명 IP 없이 오리지널 캐릭터의 흡인력 → 스티커북 아트와 캐릭터성에 투자.

### Legal / Platform Risks
- 한국 게임산업법: 확률형 아이템 확률 표시 의무(2024.3 시행) — 유료 재화가 섞인 가챠는 등급·크루별 확률을 게임 내·홈페이지에 공시.
- Google Play / App Store 정책: 루트박스 확률 공개, 연령 등급(가챠 포함 시 등급 영향), 미성년자 결제 보호.
- IAP는 영수증 검증·환불 처리가 필요한데 서버가 없음 → T2에서 로컬 검증 범위와 위험을 ADR로 결정.

### Scope Risks
- PR-SCOPE(원안 기준 UNREALISTIC) 결정 유지: **2~3개월 = MVP 완성 + 재미 검증**, 출시는 별도 마일스톤으로 재추정.
- 크루원 아트 24명 → T3로 이연. 피벗 후 크루 1명 = 얼굴 일러스트 1장 + 조각 타일 색이라 매치-3 안보다 아트 부담이 작다.
- 첫 게임이라 속도 데이터 없음 → 매 스프린트 버퍼 20%.

### Open Questions
- 미리보기가 있으면 플레이어가 실제로 "얼굴을 노리는가", 아니면 숫자만 쫓는가? → 외부 테스터 플레이테스트.
- 스테이지 목표의 기본형은 무엇이 가장 재밌나 (점수 / 특정 칸 / 방해물 / 연쇄 N)? → `/design-system`에서 정의 후 프로토타입.
- 무한 모드(놓을 곳 없을 때까지)를 MVP에 둘지, 스테이지만 둘지?
- 트레이 랜덤: 완전 랜덤 vs 스테이지 고정 시드 vs "가방"(일정 주기 보장)?

## MVP Definition

**Core hypothesis**: 플레이어는 연쇄 미리보기를 보며 얼굴 위치를 노려 조각을 놓고, 크루 능력이 도미노처럼 이어지는 순간에 재미를 느껴 "한 판 더"를 누르며, 처음 보는 사람도 "다른 블록 퍼즐과 다르다"고 말한다.

**가설 검증 기준** (제안값 — 외부 플레이테스트 후 `/playtest-report`에서 확정):
- 외부 테스터 5명 이상 중 과반이 설명 없이 3판 안에 "얼굴이 지워지면 능력이 터진다"를 스스로 말한다.
- 테스트 중 연쇄 2단 이상을 미리보기를 보고 **의도적으로** 만든 배치가 테스터당 1회 이상 관찰된다.
- 첫 판 실패·클리어 후 "한 판 더"(재시작)를 누르는 비율이 과반이다.
- "다른 블록 퍼즐과 무엇이 다른가" 질문에 과반이 얼굴/능력/연쇄를 언급한다.

**Required for MVP**:
1. 배치 보드 (8×8, 조각 3개 트레이 드래그, 줄 지우기, 놓을 곳 없으면 실패)
2. 크루 얼굴 & 능력 + 결정적 연쇄 해석기 + 드래그 중 연쇄 미리보기 (크루 6명 / 능력 6종, 데이터 기반)
3. 3인 팀 편성(= 조각 풀) + 원탭 재시작(직전 팀 유지)
4. 10스테이지 (제한 조각 수 + 목표 + 별 1~3개)
5. 게임 내 재화 가챠 (천장·중복 → 샤드·확률 표시 포함, 유료 결제 없음) + 로컬 세이브
6. 스티커북 스타일 아트 + 얼굴 능력·연쇄 연출 (기둥 1)

**Explicitly NOT in MVP** (defer to later):
- 레벨업/중복 강화, 스티커 앨범 도감 화면 (T2 이후)
- 크루 7명 이상, 방해물 종류 다수
- 유료 재화·IAP 결제 연동 (T2)
- iOS 빌드, 스토어 출시 작업
- 월드맵 연출, BGM 다수, 리더보드

### Scope Tiers (if budget/time shrinks)

각 티어는 그 자체로 완결된 빌드다 (PR-SCOPE 권고).

| Tier | Content | Features | Timeline |
| ---- | ---- | ---- | ---- |
| **T0 Godot 그레이박스 (재미 재확인)** | 보드 1개, 크루 3명, 회색 박스 아트 | 배치·줄 지우기·얼굴 능력·연쇄 미리보기 (HTML 프로토타입을 Godot로 새로 작성) | ~3~4주차 |
| **T1 MVP** | 크루 6명, 10스테이지 | 위 MVP 6항목 | ~8~12주차 (2~3개월 목표) |
| **T2 Android 소프트런치** | 크루 8~12명, 20스테이지 | + 레벨업(+20% 상한), 스티커 앨범, 유료 재화 IAP(Google Play Billing), 확률 공시 페이지, 출시 작업 | MVP 이후 별도 재추정 |
| **T3 풀 비전** | 크루 24명+, 4월드 × 15 = 60스테이지 | 모든 기능, 폴리시, iOS | 출시 후 업데이트 |
