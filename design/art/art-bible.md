## 1. Visual Identity Statement

**비주얼 규칙: "모든 것은 손으로 오려 붙인 스티커다."**

판 위의 조각, 버튼, 보상 아이콘, 결과 카드까지 화면의 모든 상호작용 대상은 종이 위에 붙은 스티커로
읽혀야 한다. 이 규칙이 애매한 결정을 정리하는 기준이다. 어떤 요소가 "화면에 떠 있는 UI"처럼 보이면
틀린 것이고, "종이에 붙어 있는 물건"처럼 보이면 맞다. 퍼즐의 핵심 동작(드래그해서 붙이기)과 시각
메타포가 같으므로 플레이어는 별도 설명 없이 "붙이고, 떼고, 다시 붙이는" 문법을 이해한다.

**지원 원칙**

1. **오려낸 윤곽 — 두꺼운 흰 테두리 + 살짝 불규칙한 실루엣** *(기둥 5 다정한 세계)*
   모든 크루 조각과 UI 버튼은 가위로 오린 듯한 흰 여백을 가진다. 완벽한 벡터 정원이 아니라 미세하게
   흔들린 손맛 윤곽이 "다정한" 수공예 느낌을 만든다. 테두리는 런타임 셰이더가 아니라 텍스처에 굽는다
   (TD 권고, Compatibility 렌더러·모바일 성능).
   *Design test*: 새 에셋이 크라프트지 배경 위에서 "붙어 있는 스티커"로 읽히지 않으면 반려한다. 테두리를
   셰이더로 할지 구울지 애매하면 → **굽는다**.

2. **얼굴이 주인공 — 얼굴 칸은 항상 먼저 보인다** *(기둥 1 도미노의 손맛, 기둥 3 보이는 연쇄)*
   얼굴은 능력의 스위치이므로 판에서 가장 먼저 읽혀야 한다. 얼굴 칸만 가지는 세 가지: 칸 경계를 넘치는
   크기(3절), 몸통보다 넓은 흰 여백 + 흰 반짝 스프라이트(4절), 그리고 **판 위에서 유일한 잉크-온-크림
   고대비**(이목구비). 몸통 칸은 이 셋 중 어느 것도 갖지 않는다. 능력 발동 연출의 문법은 고정한다:
   **스티커가 모서리부터 들썩 떼어짐 → 효과 → 다시 착 붙음(또는 날아가 사라짐)**.
   *Design test*: 판을 흑백으로 바꾼 스크린샷에서도 얼굴 칸을 1초 안에 모두 찾을 수 있는가? 몸통 장식과
   얼굴 가독성이 충돌하면 → **얼굴**.

3. **종이 위의 빛 — 한 방향 조명, 붙어 있으면 낮은 그림자, 떼어지면 높은 그림자** *(기둥 3 보이는 연쇄)*
   흰 테두리와 판(#f3e8d3)의 명도 대비는 1.19:1이라 테두리만으로는 스티커가 판에서 분리되지 않는다.
   그래서 모든 스티커는 **좌상단 광원**, 우하단으로 떨어지는 짧고 부드러운 접지 그림자(잉크 브라운,
   반투명)를 가진다. 그림자 높이가 곧 상태다: 붙음 = 1–2px 그림자, 드래그 중·떼어짐 = 6–10px 그림자 +
   약간 확대. 그림자는 미리 블러한 실루엣 스프라이트이며 상태마다 오프셋·불투명도만 바꾼다.
   *Design test*: 상태 표현을 새 색이나 글로우로 할지 그림자 높이로 할지 애매하면 → **그림자 높이**.

4. **앨범 메타포 — 수집 화면은 스티커 앨범** *(기둥 2 크루가 곧 전략, 기둥 5)*
   도감은 앨범 페이지, 미획득 크루는 점선 빈칸 실루엣, 가챠는 "스티커 팩 개봉". 희귀 크루원의 홀로그램
   테두리는 **UI(앨범·가챠·팀 편성) 전용**이며 판 위에서는 쓰지 않는다 — 판에서 반짝임은 얼굴 칸의 몫이다.
   *Design test*: 수집 UI가 앨범 메타포를 깨거나, 판 위에 홀로 효과가 등장하면 반려.

**회피 목록 (오리지널 룩 유지)** — 아래 중 하나라도 해당하면 반려한다.
- *Block Blast 계열*: 광택 베벨·젤리 하이라이트가 있는 보석형 블록, 어두운 남색 판, 네온 글로우 줄 지우기.
  우리 판은 밝은 종이, 블록은 무광 스티커, 지우기는 "떼어짐"이다.
- *Disney 계열*: 반사광이 큰 유리알 눈, 3D 렌더처럼 매끈한 그라데이션, 원 머리 + 큰 원 귀 두 개 실루엣.
  우리 얼굴은 잉크 점 눈·선 입의 평면 그림이며 그라데이션은 쓰지 않는다(단색 + 그늘색 1단).

## 2. Mood & Atmosphere

2D 게임이므로 "조명"은 3D 광원이 아니라 **종이의 색온도, 그림자 높이, 배경 비네트, 입자 양**으로 다룬다.
모든 상태는 같은 크라프트지 세계 안에 있고, 상태 간 차이는 이 네 레버로만 만든다. 광원 방향(좌상단)은
어떤 상태에서도 바꾸지 않는다 — 바꾸면 그림자 높이 언어가 깨진다. 색온도·명도 변화는 화면 전체 모듈레이트
한 겹으로 처리하고(셰이더 불필요), **판 위 얼굴 칸의 대비는 어떤 상태에서도 낮추지 않는다**(원칙 2).

| 게임 상태 | 감정 목표 | 조명/색온도 | 분위기 형용사 | 에너지 | 무드를 싣는 요소 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| **판 읽기 (대기)** | 차분한 집중, "어디 둘까" 생각할 여유 | 따뜻한 오후 햇살 톤, 중간 대비, 비네트 약하게 | 아늑한, 정돈된, 조용한 | 사색적 | 판 바깥 크라프트지의 섬유 질감, 정지한 스티커(1px 그림자), 얼굴 칸의 느린 반짝(약 3초 간격, 칸마다 엇갈림) |
| **드래그 + 연쇄 미리보기** | 기대감, "연쇄 3 예상!"의 설렘 | 판 외곽 살짝 어둡게(-8% 명도), 판 위 미리보기 칸만 밝게 | 집중된, 들뜬, 선명한 | 고조 | 드래그 조각의 높은 그림자, 지워질 칸의 점선 하이라이트, 발동 순서 번호 배지 |
| **연쇄 발동 (페이오프)** | 압도적 쾌감 — 게임에서 가장 시끄러운 순간 | 단계마다 짧은 밝기 펄스(+10%, **초당 3회 이하**, 설정에서 끌 수 있음), 크루 색 입자 | 폭발적, 경쾌한, 리드미컬한 | 열광적 | 스티커 떼어짐→효과→재부착, 단계 컷인(크루 얼굴 스티커가 화면 가장자리에 착 붙음), 종이 조각 컨페티 |
| **스테이지 클리어** | 뿌듯함, 수집한 느낌 | 가장 따뜻하고 밝은 상태, 저대비, 비네트 없음 | 축하하는, 포근한, 반짝이는 | 들뜬 뒤 안정 | 금색 별 스티커가 결과 카드에 하나씩 착착 붙음, 앨범에 붙이는 손맛 |
| **실패 ("꽉 찼다")** | 웃음, 무해한 아쉬움 — 긴장 아님 | 색온도 그대로, 채도만 살짝 낮춤(-15%). 어둡게 하지 않는다 | 장난스러운, 머쓱한, 가벼운 | 잠깐 멈춤 | 스티커북이 빵빵하게 부풀어 "끙" 하는 연출, 크루 얼굴이 머쓱한 표정 스티커로 교체, 크게 보이는 원탭 재시작 |
| **팀 편성 / 앨범** | 애착, 고르는 즐거움 | 중성~따뜻, 저대비, 앨범 페이지 크림색 | 차분한, 소중한, 정리된 | 측정된 | 앨범 페이지와 비닐 포켓, 희귀 크루 홀로 테두리(UI 전용) |
| **가챠 (스티커 팩 개봉)** | 두근거림 → 기쁨 | 개봉 직전 배경 어둡게(유일하게 어두워지는 상태), 개봉 순간 빛 번짐 | 두근거리는, 신비한, 반짝이는 | 고조→폭발 | 팩 포장지 찢기, 등급별 테두리(일반 흰색 / 희귀 홀로), 확률·천장 정보는 어둡게 하는 레이어 **위**에 두어 항상 같은 밝기로 보이게 |
| **메뉴 / 월드맵** | 편안한 귀환, "한 판 더"의 문턱이 낮음 | 기본 크라프트 톤, 중간 대비 | 친근한, 정돈된, 가벼운 | 측정된 | 다이어리 꾸미기 레이아웃, 큰 스티커 버튼 |

**구분 원칙**: 판 읽기와 연쇄 발동은 가장 멀리 떨어진 상태여야 한다(정적 vs 폭발). 실패는 **절대 어두워지지
않는다** — 어두워지는 것은 가챠 개봉 직전뿐이며, 그것도 기대감 연출이지 위협이 아니다 (기둥 5). 상태 구분은
색 하나에 의존하지 않는다: 각 상태는 색온도 외에 고유한 움직임(정지 / 떠오름 / 떼어짐 / 붙음 / 부풂)을 가진다.

## 3. Shape Language

**기본 어휘: 둥근 사각형 + 오려낸 여백.** 세계의 모든 형태는 "모서리가 둥근 사각 칸"과 "그것을 둘러싼
흰 오려낸 여백"으로 이뤄진다. 퍼즐 판이 8×8 격자이므로 각진 사각형은 피할 수 없지만, 모서리 반경
(칸 크기의 약 22%, 프로토타입 값)과 불규칙한 흰 여백이 딱딱함을 지운다. 날카로운 꼭짓점, 가시, 톱니
형태는 쓰지 않는다 (기둥 5 — 위협적인 형태 없음). 플레이어가 받는 감정 신호는 "말랑하고 만져도 되는 것"이며,
이것이 게임 이름(말랑)과 실패해도 안전하다는 약속을 형태로 전달한다.

**캐릭터(크루) 실루엣**
- 크루는 조각 위의 **얼굴 1칸**으로 존재한다. 얼굴 = 크루 본색의 둥근 머리 + 얼굴 크림 주둥이/볼 + 잉크
  이목구비. 실루엣 판독은 판 위 크기(약 120px @1080 폭)와 썸네일(앨범·컷인, 약 64px)에서 모두 통해야 한다.
- 크루마다 **머리 윤곽에 고유한 돌출 1개**를 둔다: 냥이 = 끝이 둥근 삼각 귀 두 개, 곰곰 = 작은 반원 귀 두 개,
  삐약 = 머리 위 깃털 한 가닥 + 부리. 이후 크루도 "귀/뿔/깃털/잎 등 윤곽 돌출 1개"로 구분하며, 같은 돌출
  유형을 두 크루가 공유하지 않는다. 흑백 실루엣만으로 6명을 구분할 수 있어야 한다 (색약 대응의 1차 방어선, 4절).
- **곰곰 귀 제한**(회피 목록): 귀 지름은 머리 지름의 30% 이하, 귀 중심은 머리 상단 ±50° 바깥(옆으로 벌어지게),
  귀 안쪽에 그늘색 반원. 큰 원 귀가 위 대각선에 붙은 실루엣은 반려.
- 얼굴은 칸 경계를 살짝 넘치게(약 110%) 그리고 이웃 칸 위에 그린다. 몸통 칸은 무늬만 있고 표정이 없다.
- 표정은 점 눈 + 선 입이 기본이며, 상태별 표정 교체(기본 / 발동 / 머쓱)는 같은 얼굴 위 이목구비 스프라이트만
  바꾼다 (얼굴 1명당 표정 3장, 섹션 5에서 확정).

**조각(몸통) 형태**
- 조각 모양 자체가 크루 정보다 (기둥 2: 크루 = 조각 풀). 조각 전체가 **한 장의 스티커**로 오려져야 한다 —
  칸마다 따로 테두리를 두르지 않고, 조각 외곽 전체에 흰 여백 하나를 두른다. 이것이 "한 조각 = 한 스티커"를
  즉시 읽히게 한다. 판에 붙은 뒤에도 칸 사이에는 얇은 그늘색 접선만 남겨 칸 수를 셀 수 있게 한다.

**환경(판/배경) 기하**
- 판은 둥근 사각 트레이, 칸은 살짝 눌린 홈(내부 그림자 1px)으로 "스티커를 붙일 자리"를 표현한다.
- 배경은 크라프트지의 유기적 섬유 질감과 테이프 조각·도장 같은 다이어리 꾸미기 소품. 배경 형태는 모두
  **저대비·비상호작용·흰 여백 없음**이라 판 위 스티커보다 항상 뒤로 물러난다 (흰 여백 = 만질 수 있음, 4절).

**UI 형태 문법**
- UI는 별도의 HUD 언어가 아니라 **같은 스티커 문법**을 따른다: 버튼 = 흰 여백 + 접지 그림자를 가진 둥근
  스티커, 누르면 그림자가 0으로 꺼지며 "꾹 눌림". 패널 = 마스킹테이프로 붙인 종이 카드(살짝 기울기 ±2° 이내).
- 터치 대상은 최소 약 64px(1080 폭 기준, 흰 여백 포함). 시각적으로 작은 아이콘도 히트 영역은 64px 이상.

**주연 형태 vs 조연 형태**

| 위계 | 대상 | 형태 수단 |
| ---- | ---- | ---- |
| 1 (가장 먼저) | 얼굴 칸, 연쇄 미리보기 번호 | 칸 넘침, 넓은 흰 여백 + 반짝 스프라이트, 잉크-온-크림 최고 대비 |
| 2 | 트레이·드래그 중 조각 | 한 장 스티커 윤곽, 높은 그림자 |
| 3 | 판 위 몸통 칸 | 크루 색 + 저대비 무늬, 낮은 그림자 |
| 4 | UI 버튼·목표 표시 | 스티커 버튼, 화면 상하단 고정 |
| 5 (가장 뒤) | 배경 소품·종이 질감 | 저대비, 무채색 계열, 그림자·흰 여백 없음 |

## 4. Color System

**색 철학**: 따뜻한 저채도 종이 위에 **중채도 원색 = 크루원**. 색은 크루의 이름표이며, 세계의 다른 어떤 것도
크루 색을 빌려 쓰지 않는다 (예외: 연쇄 입자·컷인 테두리는 해당 크루 색). 판과 배경이 저채도라 조각이 항상
먼저 보인다. 그라데이션은 쓰지 않는다 — 모든 색면은 본색 + 그늘색 1단(종이 인쇄물처럼).

**기본 팔레트 (세계)**

| 역할 | 이름 | Hex | 의미 / 사용처 |
| ---- | ---- | ---- | ---- |
| 바탕 | 크라프트지 | `#e8d9bd` | 세계의 기본 종이. 화면 배경 |
| 바탕 어둠 | 크라프트 그늘 | `#d6c29f` | 배경 소품, 비네트, 판 테두리 |
| 판 | 판 종이 | `#f3e8d3` | 8×8 판 칸 바탕. 크라프트보다 밝아 판이 무대로 떠오름 |
| 스티커 흰색 | 스티커 백 | `#fffdf8` | 모든 오려낸 여백, 패널 바탕. 순백 대신 미색 — 종이 세계에서 순백은 튄다 |
| 잉크 | 잉크 브라운 | `#3b2f25` | 텍스트, 이목구비, 주 행동 버튼, 접지 그림자(30–40% 불투명). 순검정은 쓰지 않는다 |

| 얼굴 크림 | 얼굴 바탕 | `#fbf1d6` | 얼굴 주둥이·볼 영역, 미리보기 예상 칸 |

**크루 색 (색 = 크루원)** — 크루 색은 **명도 띠**(상대 휘도 L) 3개에 나눠 배정한다: 밝음 L ≥ 0.45,
중간 0.22–0.35, 어두움 ≤ 0.16. 색약 충돌 쌍은 반드시 서로 다른 띠에 둔다.

| 크루 | 본색 | 그늘색 | 명도 띠 (L) | 몸통 무늬 (색약 백업) | 비고 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 삐약 | `#f2c230` | `#c99a10` | 밝음 (0.58) | 물방울 | 프로토타입 값 유지 |
| 냥이 | `#e8574a` | `#b83a30` | 중간 (0.24) | 줄무늬 | 프로토타입 값 유지 |
| 곰곰 | `#2e6bc6` | `#1f4b8f` | 어두움 (0.15) | 민무늬 + 둥근 얼룩 1개 | **변경** (프로토타입 `#3f7fd9`, L 0.21 — 냥이와 흑백 구분 불가) |
| 슬롯 6 | `#f29cc0` (분홍, 잠정) | `#c56f95` | 밝음 (0.46) | 크루 확정 시 지정 | 냥이와 제1색맹 충돌 → 띠로 분리 |
| 슬롯 5 | `#9a72d4` (보라, 잠정) | `#7150a8` | 중간 (0.24) | 크루 확정 시 지정 | 곰곰과 충돌 → 띠로 분리 |
| 슬롯 4 | `#2a7a45` (초록, 잠정) | `#1c5530` | 어두움 (0.15) | 크루 확정 시 지정 | 냥이와 적록 충돌 → 띠로 분리 |

- 그늘색은 조각 아래쪽 1/4 음영과 "들썩 떼어짐" 시 뒷면 색으로 쓴다.
- **몸통 무늬는 본색 명도 ±15% 이내**로 그린다 (흰색·잉크 무늬 금지). 무늬가 강하면 얼굴의 고대비가 묻힌다.
- 삐약 부리 주황(`#e8873a`, 프로토타입)은 얼굴 내부 디테일로만 허용 — 크루 색으로 승격하지 않는다.
- 크루 7명 이상(T2+)은 색이 겹칠 수밖에 없으므로 **같은 팀 3인 안에서만 색이 유일하면 된다**는 규칙으로
  확장한다. 팀 편성 화면이 같은 색 계열 또는 같은 명도 띠의 두 크루를 함께 넣을 때 **경고만** 하자고 제안한다 —
  편성을 막을지는 게임 디자인 결정이라 팀 편성 GDD(game-designer)에 넘긴다.

**의미 색 (세계의 색 어휘)** — 각 색이 왜 그 의미인지:
- **크루 색** = "이 크루의 것" (조각, 능력 입자, 컷인 테두리). 이름표이므로 그 외 의미로 쓰면 이름이 흐려진다.
- **금색 `#ffe278`** = 보상·강조 (별, 코인, 연쇄 단계 숫자 하이라이트). 문구점 금박 스티커에서 온 색이고, 따뜻한
  종이 위에서 가장 밝고 "반짝이는" 색이라 받는 것에만 쓴다. 얼굴 강조·버튼에는 쓰지 않는다.
- **스티커 백 `#fffdf8`** = 상호작용 가능 (흰 여백이 있으면 만질 수 있다). 그래서 배경 소품·방해물에는 흰
  여백을 두지 않는다. 얼굴 칸의 반짝 스프라이트도 이 색이다 — "여기를 건드리면 일이 난다".
- **잉크 브라운** = 정보와 결정 (텍스트, 번호 배지 바탕, 주 행동 버튼). 펜으로 쓴 글씨처럼 "읽는 것".
- **위험/실패 전용 색은 두지 않는다.** 실패는 빨강 경고가 아니라 연출(부풀어 오른 스티커북)로 전달한다
  (기둥 5). 빨강은 이미 냥이의 색이라 경고에 쓰면 의미가 충돌한다.
- **방해물**(얼어붙은 얼굴, 지워지지 않는 칸)은 크루 색·흰색이 아닌 **무채색 + 고유 텍스처**로 표시한다:
  얼음 = 차가운 회색 `#b9c3c9` 결정면 + 잉크 빗금, 돌 = 회갈색 `#9a8c7e` 점묘. 얼음에 덮인 얼굴은 이목구비가
  비쳐 보여 "얼굴이 갇혀 있다"가 읽혀야 한다.

**영역(월드)별 색온도 규칙**
MVP는 단일 월드. 풀 비전 4월드는 **배경 종이 색만** 바꾼다(예: 크라프트 → 하늘색 도화지 → 연두 모눈지 →
라벤더 편지지, 모두 저채도·명도 L* 80 이상). 판 종이·스티커 백·잉크·크루 색은 월드와 무관하게 고정한다 —
크루 색이 월드에 따라 달라 보이면 기둥 3이 깨진다. 월드 배경 색상은 어떤 크루 본색과도 같은 색상 계열로
보이지 않게 채도를 낮춘다(예: 하늘색 도화지가 곰곰을 삼키지 않게).

**UI 팔레트 (월드 팔레트와의 차이)**
- UI는 같은 스티커 백·잉크·금색을 쓴다. 차이는 두 가지뿐이다:
  1. **주 행동 버튼**(시작, 재시작)은 **잉크 브라운 `#3b2f25` 바탕 + 스티커 백 글자 + 흰 오려낸 여백 +
     접지 그림자**. 크라프트 위에서 가장 진한 면이라 크루 색을 빌리지 않고도 가장 먼저 눌릴 곳으로 보인다
     (프로토타입의 산호색 버튼은 냥이 색이라 폐기). 보조 버튼은 스티커 백 바탕 + 잉크 글자.
  2. **홀로그램**(희귀 등급 테두리, 가챠 개봉)은 UI 전용 그라디언트 셰이더 — 유일하게 허용되는 셰이더 효과이자
     유일한 그라데이션. 판 위·크루 조각에는 금지.
- 어두운 툴팁 바탕은 진한 잉크 `#2b211a`, 그 위 강조 글자는 금색.

**색약 안전 — 색만으로 구분하지 않는다**

대비 계산(WCAG 상대 휘도, art-director 재계산 2026-11-07):

| 쌍 | 대비 | 판정 / 대응 |
| ---- | ---- | ---- |
| 잉크 / 크라프트 | 9.6:1 | 본문 텍스트 OK |
| 잉크 / 스티커 백 | 13.2:1 | 버튼 글자 OK |
| 잉크 / 얼굴 크림 | 11.9:1 | 이목구비 — 판 위 최고 대비, 얼굴 전용 (원칙 2) |
| 스티커 백 / 판 종이 | 1.19:1 | **분리 불가** → 모든 스티커에 접지 그림자 필수 (원칙 3) |
| 스티커 백 / 크라프트 | 1.37:1 | 분리 불가 → UI 스티커도 그림자 필수 |
| 삐약 노랑 / 판 종이 | 1.38:1 | **분리 불가** → 그림자 + 그늘색 하단 음영 + 흰 여백 바깥 그림자로 형태 확보 |
| 냥이 빨강 / 판 종이 | 2.9:1 | 그림자로 보강 |
| 곰곰 파랑(신) / 판 종이 | 4.3:1 | OK (구 `#3f7fd9`는 3.3:1) |
| 냥이 빨강 / 곰곰 파랑(신) | 1.46:1 (명도) | 흑백에서 구분 가능해짐 (구 값 1.15:1) |

색약 시 충돌 위험 쌍과 필수 백업 — 모든 충돌 쌍은 서로 다른 명도 띠에 있다:
- **냥이(빨강, 중간) ↔ 슬롯 4(초록, 어두움)**: 적록 색약(제1·2색맹)에서 탁한 노랑갈색으로 근접.
- **곰곰(파랑, 어두움) ↔ 슬롯 5(보라, 중간)**: 제1색맹·제3색맹에서 근접.
- **냥이(빨강, 중간) ↔ 슬롯 6(분홍, 밝음)**: 제1색맹에서 근접.
- **같은 띠 쌍**(삐약↔분홍, 냥이↔보라, 곰곰↔초록)은 일반 색각·대부분의 색약에서 색상이 멀지만 흑백에서는
  가까우므로 아래 1–3번 백업에 의존한다.

모든 크루는 색과 독립된 **세 겹의 백업**을 가진다:
1. **얼굴 실루엣의 윤곽 돌출**(3절) — 흑백에서 구분.
2. **몸통 무늬**(줄무늬 / 민무늬+얼룩 / 물방울 / …) — 몸통 칸만 보여도 구분. 무늬는 텍스처에 구워 넣는다(비용 0).
3. **조각 모양** — 크루마다 조각 모양 풀이 다르다 (게임 규칙).

연쇄 미리보기·발동 순서는 색이 아니라 **번호 배지(잉크 원 + 스티커 백 숫자) + 점선 하이라이트**로 표시하고,
예상 칸은 얼굴 크림 바탕 + 점선 윤곽으로 그린다. 점선 색은 크루 색이 아니라 잉크로 한다(프로토타입은 크루 색 —
교체). 검수 기준: 흑백(그레이스케일) 스크린샷과 제1·2·3색맹 시뮬레이션 스크린샷에서 (a) 판 위 모든 크루를
구분할 수 있고 (b) 얼굴 칸을 1초 안에 모두 찾을 수 있어야 한다 — `production/qa/evidence/`에 보관.

## 5. Character Design Direction

[To be designed] — the player character's visual archetype, how players tell

## 6. Environment Design Language

[To be designed] — architectural style and its tie to the world's culture,
texture philosophy (painted, PBR or stylised, and why), prop density rules per
area type, and environmental storytelling guidelines.

## 7. UI/HUD Visual Direction

[To be designed] — diegetic versus screen-space HUD, typography (personality,
weight, size hierarchy, minimum readable size), iconography style, UI animation
feel, and any art-direction versus readability conflict and how it was decided.

## 8. Asset Standards

[To be designed] — file formats, naming convention, texture resolution tiers,
LOD levels, export settings, and the engine's hard limits (poly budgets per
asset category, texture memory, material slots). Where an art preference and a
technical limit disagree, record both and the trade-off chosen.

## 9. Reference Direction

[To be designed] — 3–5 references (games, films, art styles or artists). For
each: the specific element to take from it, and what to avoid so the result
does not read as a copy.
