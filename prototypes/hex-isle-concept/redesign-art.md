## 1. 렌더링 모델 — 해상도·픽셀 스케일

### 1.1 저해상도 버퍼 + 정수 최근접 확대
- 모든 월드 렌더링은 **저해상도 오프스크린 버퍼**에 한다. 1 복셀 = 버퍼 1픽셀(가로 기준).
- 화면 출력은 `imageSmoothingEnabled = false` 로 **정수 배율 k** 확대. CSS 에도 `image-rendering: pixelated`.
- k 결정(자동 피트, §11): `k = max(2, floor(min(0.88·screenW / islandW, 0.82·screenH / islandH)))`, 버퍼 크기 = `ceil(screen / k)`. 즉 버퍼가 화면에 맞춰 변하고 섬은 항상 화면을 채운다.
- 기준 예: 1920×1080 화면 → k=3, 버퍼 640×360. 1280×720 → k=2, 버퍼 640×360.
- **비정수 확대·회전 후 보간 금지.** 모든 `drawImage` 좌표는 정수로 반올림.

### 1.2 투영
- 카메라 yaw θ 만 회전. 기울기 고정: 지면 세로 압축 `TILT = 0.55` (단면 이미지를 세로 0.55 배로 그림).
- **층 간격 = 버퍼 1픽셀** (단면 z 는 화면에서 z 픽셀 위로). 이 비율이 장난감 같은 짧고 통통한 높이감을 만든다.
- 그리기 공식 (모델 단면 s, 모델 높이 z):
  `screen = project(rotate(worldXY, θ)) ; 각 단면을 θ 회전 + 세로 TILT 압축 후 (sx, sy - z) 에 그림`.

### 1.3 월드 스케일 (복셀 단위)
| 항목 | 크기 |
|---|---|
| 육각 칸 (flat-top) 외접 반지름 R | **22 복셀** (모서리 간 44, 변 간 ≈ 38) |
| 칸 판 두께 | 미배치 3 / 배치 4 슬라이스 |
| 섬 최대 (~100칸, 반경 ~5.5칸) | 지름 ≈ 420 복셀 → 화면 420 × (420·0.55 + 30) ≈ 420 × 260 버퍼 픽셀 |

| 양 | 5×3×4 |

R=22 는 칸당 나무 9그루(수관 지름 7~9, 30% 겹침)가 들어가는 최소 크기다. 이보다 작으면 숲 디테일 요구를 못 맞춘다.

## 3. 복셀 음영 굽기 (로드 시 1회)

각 모델은 `W×D×H` 의 재질 ID 격자(0 = 빈칸). 단면 이미지를 만들 때 복셀마다 램프 단계를 고른다:

1. **윗면 노출** (z+1 이 비어 있음) → `L`.
2. 윗면 비노출이고 **빛 쪽 측면 노출** (월드 광원 방향 이웃이 빈칸) → `B`.
3. 그 외 노출 측면 → `S`.
4. **AO:** 같은 층 8이웃 + 위층 9이웃 중 채워진 수 ≥ 12, 또는 모델 바닥 2층(지면 접촉) → 한 단계 어둡게 (최대 `D`).
5. **잎 질감:** 잎 재질의 `L` 복셀 중 시드 8% 는 꽃/액센트가 아니라 한 단계 밝은 점(활엽수는 `#B4E08A`)으로 — 반짝이는 잎 결.
6. **수관 하단 그늘:** 수관 높이 하위 30% 의 잎 복셀은 한 단계 어둡게.

광원: 월드 고정, 화면 기준 기본 yaw 에서 좌상단(방위 315°, 고도 45°). 측면 판정은 월드 방향이므로 **모델의 배치 회전(rot)** 에 따라 모델 공간 광원이 달라진다 → 굽기 키는 `(variant, rot8)` (8방향 버킷). 카메라 yaw 가 돌면 빛도 같이 도는 것처럼 보이는 것은 의도(탁자 위 장난감을 돌리는 느낌).

## 4. 지면 스택 — 섬 전체가 하나의 스프라이트 스택 ("베이지 판" 폐기)

칸 판·풀·꽃·밭·해변을 **월드 공간 픽셀 맵 묶음(섬 지면 스택)** 으로 그린다. 1 픽셀 = 1 복셀, 맵 크기 ≈ 448×448.

| 슬라이스 z | 내용 |
|---|---|
| 0~1 | 칸 판 측면 나무(판 측면 램프). 섬 외곽과 해변 아래에서만 보임 |
| 2 | 흙/판 상단 (측면) |
| 3 | 미배치 칸 윗면 = **야생 들판** (채도↓ 램프 + 듬성 풀) |
| 4 | 배치 칸 윗면 = 종류별 바닥(초원, 목장 풀, 밭 흙, 숲 바닥, 마당·광장 돌, 연못은 구멍) |
| 5 | 풀잎 1단, 꽃대, 싹, 밀 1단, 갈대 1단, 연잎(물 칸) |
| 6 | 풀잎 끝, 꽃송이(1~2픽셀), 밀 2단 |
| 7~9 | 밀 3~5단(익은 밭만), 갈대 2~4단 |

- 지면 스택은 매 프레임 **슬라이스 10장을 회전해서 그림** (각 448² 이미지 1회 drawImage). 0~2 는 같은 마스크라 하나의 이미지를 세 번.
- **칸 경계 병합이 공짜로 된다:** 맵은 월드 공간 한 장이므로 같은 종류 인접 칸의 바닥은 이어 칠한다. 다른 종류 사이는 경계 픽셀에 2~3픽셀 노이즈 지그재그. 칸 경계를 알리는 선은 **미배치 칸끼리 사이의 z=3 → 배치 칸 z=4 단차** 하나뿐 (판 느낌 유지).
- 배치 시 해당 칸 영역만 맵을 다시 그림 (부분 재굽기, 칸 1개 ≈ 1,700 픽셀 × 10 슬라이스).

### 4.1 초원(빈 땅·초원 바닥) 드레싱 — 칸당, 시드
| 요소 | 개수 | 픽셀 규칙 |
|---|---|---|
| 풀 다발 | 25~40 | z5 에 1×2 픽셀 `S`, z6 에 끝 1픽셀 `L`. 다발 = 2~4 줄기 |
| 꽃 무리 | 1~3 무리 × 3~6 송이 | z5 줄기 `B`, z6 꽃 액센트 1픽셀(가끔 2×1). 무리당 1색, 칸당 최대 2색 |
| 바닥 결 | 전체 | z4 바닥에 시드 디더: `B` 70% / `L` 15% / `S` 15% 체커가 아닌 블루노이즈 패턴 |
| 작은 돌 | 0~2 | 모델 `rock_s` (§5.2) |
| 흙길 | 조건부 | 집↔집/밭/목장 칸 사이, 칸 중심→공유 변 중점 2차 베지어, 폭 3~4픽셀, z4 를 흙길 램프로. 가장자리 1픽셀은 풀 다발로 덮음 |

미배치 칸은 같은 규칙에 개수 40%, 꽃 없음, 채도↓ 램프 → 놓을 수 있는 땅이지만 "아직 손대지 않은" 들판으로 읽힘.

## 6. 칸별 배치 — 시드 변주

- 시드: `rng = mulberry32(hash(q, r, islandSeed, salt))`, salt = 요소 종류별 상수(풀=1, 꽃=2, 나무=3, 하층=4, 소품=5, 동물=6). **같은 섬은 항상 같은 모습** (Anti-pillar: 처리 중 무작위 금지와 일치 — 장식도 결정적).
- 배치: 칸 마스크 내부 포아송 디스크. 최소 간격 = 두 모델 반경 합 × 0.7 (나무 수관 30% 겹침).
- 모델 인스턴스마다: 변주 index(3 중 1), **배치 회전 rot = rng 0~63 (yaw 스텝 단위)**, 굽기용 rot8 = rot >> 3.
- 같은 변주라도 회전이 다르면 다른 나무로 읽힌다 — 64회전 × 3변주 × 크기 3 로 충분.
- 다시 생성되는 것은 상태가 바뀐 칸(배치, 무리 크기 변경)과 그 이웃(병합 규칙 때문)뿐.

## 7. 숲 — 최우선 디테일

### 7.1 칸당 나무 수
`n = clamp(5 + floor(clusterSize / 2), 5, 9)` → 무리 1~2: 5~6, 3~4: 7, 5~6: 8, 7+: 9. 큰 나무 1~2그루 중심 근처, 작은 나무는 가장자리.

### 7.2 수종 혼합 (칸 위치 기반, 결정적)
- `edgeness = 비숲 이웃 수 / 6`.
- 가장자리 (edgeness ≥ 0.5): 활엽 45 / 자작 35 / 침엽 15 / 과일 5 %. 크기 s·m 위주.
- 중간: 활엽 50 / 침엽 30 / 자작 20.
- 내부 (edgeness = 0): 침엽 55 / 활엽 40 / 자작 5. 크기 m·l 위주.
- 집 칸에 인접: 나무 1~2그루를 `tree_fruit` 로 교체 (마을 과수원).

### 7.3 수관 병합과 내부 어둠
- **브리지 나무:** 숲 칸 둘이 맞닿은 변마다 변 중점 ±6복셀에 나무 1~2그루. 시드 = 두 칸 좌표를 정렬한 해시 → 어느 칸에서 생성해도 같은 결과, 중복 생성 금지(작은 좌표 쪽 칸이 소유).
- **숲 바닥 (지면 스택 z4):** 숲 무리 합집합에 대해 거리장(가장 가까운 비숲 픽셀까지 거리 d) 계산 → `d < 4` 숲 바닥 `L` + 가끔 꽃, `d < 10` `B`, `d < 18` `S`, 그 이상 `D`. 이것만으로 "밝은 가장자리 · 어두운 중심" 이 생긴다.
- **내부 수관 색:** 내부 칸 나무는 굽기 시 잎 램프 전체를 한 단계 어둡게 쓴 변주(`_deep`)를 사용.
- 경계선 없음: 숲 바닥이 칸 경계를 넘어 이어지고 브리지 나무가 이음매를 덮는다.

### 7.4 하층 식생 (칸당, 시드)
| 요소 | 개수 | 조건 |
|---|---|---|
| `bush_s/m` | 2~4 | 가장자리 칸에 많이 |
| `fern` | 3~6 | 전 단계 |
| 버섯 | 0~3 | 내부 칸 ≥ 1, 그루터기·통나무 옆 우선 |
| `rock_s/m` | 0~2 | |
| `log_fallen` | 0~1 | 오래된 숲 단계만 |
| `stump` | 0~1 | 숲 단계 이상 |
| 이끼 패치 | 2~5 | 지면 스택, 내부일수록 많이 |

### 7.5 얼룩 햇빛
- 숲 바닥 위 **햇살 점 오버레이**: 칸당 4~8개, 2×1~3×2 픽셀, 색은 해당 바닥 램프보다 2단계 밝게. 정적 지면 스택이 아니라 별도 작은 레이어.
- 애니메이션: 0.5초마다 각 점이 시드 순서로 켜짐/꺼짐(50% 듀티), 프레임 보간 없음 — 픽셀 아트식 깜빡임.
- 수관 윗면의 반짝 점(§3-5)이 위쪽 짝.

### 7.6 성장 단계
| 단계 | 무리 크기(제안) | 변화 |
|---|---|---|
| 1 묘목밭 | 1~2 | 5~6 중 3그루가 `sapling`, 나머지 `tree_*_s`. 바닥 = 초원 + 흙 동그라미. 하층: 고사리만. 숲 바닥·거리장 없음 |
| 2 숲(그로브) | 3~5 | 묘목 → s/m 성목. 7~8그루. 숲 바닥 거리장, 덤불·바위·그루터기. 브리지 나무. 햇살 점 |
| 3 오래된 숲 | 6+ | 9그루 m/l, 무리 중심 칸에 `tree_ancient`. 내부 `_deep` 변주, 버섯·쓰러진 통나무·이끼 최대. 새 1~2마리 수관에서 날아오름(갈매기 모델 재색칠, 갈색) |

**전환 연출 — 슬라이스 상승 (Anchor 원칙 2 "톡 솟는다"):** 새 모델은 단면을 아래부터 차례로 드러냄 (0 → H, 180ms), 끝에서 전체 스택이 1픽셀 위로 튀었다 내려옴(2프레임). 교체되는 묘목은 위에서부터 단면을 숨겨 사라지고 새 나무가 솟는다. 칸별 60ms 스태거. 비정수 스케일 애니메이션은 쓰지 않는다(픽셀 깨짐).

## 9. 바다와 해안

1. **바다 평면 (z0, 지면 스택 외부 큰 맵):** 섬 외곽까지의 거리장 → 0~6 모래톱 물 `#9EDCCB`, ~16 얕은 `#6CC6BA`, ~40 중간 `#44A0A4`, 그 이상 깊은 `#2E7C88`. 경계는 **2×2 베이어 디더**로 2픽셀 섞기 (픽셀 아트식 그라데이션).

3. **거품:** 해변 외곽선 바깥 1~3픽셀에 거품 픽셀 줄 2개. 4프레임 순환(4fps): 프레임마다 줄이 바깥으로 1픽셀 이동하며 일부 픽셀이 사라짐(시드 대시). 보간 없음.
4. **물결 반짝:** 바다 위 1~3픽셀 `#B4E8E6` 짧은 줄 20~30개, 2초 주기로 나타났다 사라짐.
5. **해안 소품:** `shore_rock` 3~6 클러스터, 일부 반쯤 잠김. 해변에 조개·유목 1픽셀 액센트 소량.

## 10. 애니메이션 — 스프라이트 스택 방식

| 종류 | 방법 |
|---|---|
| **흔들림 (나무·풀·밀·갈대)** | 단면별 수평 오프셋 `dx(z) = round(A · (z / H)² · s)`, `s ∈ {0, +1, 0, −1}` 4프레임, 5fps. 나무는 수관 단면만(A = 1~2픽셀, 거목 2), 줄기 고정. 지면 스택의 z5~9 도 같은 방식으로 슬라이스 통째 오프셋(z5 0, z7 ±1, z9 ±1) → 들판 전체 물결. 인스턴스 위상 = 시드 → 동시에 흔들리지 않음 |
| **배회 (양·주민·배·개)** | 스택 자체를 이동. 진행 방향 = 8방위 → 그리기 회전 = 카메라 yaw 스텝 + 방향 스텝 (같은 캐시 사용). 걷기 = 스택 전체 2프레임 1픽셀 들썩. 양은 2~4초마다 고개 숙임(머리 복셀 z−1 변주 프레임). 경로는 칸 내부, 시드 고정 |
| **연기** | 2×2 → 1×1 흰 픽셀 3~4개가 위로 올라가며 사라짐 (스택 아님) |
| **배치·성장 팝** | 슬라이스 상승 (§7.6) |
| **연쇄 강조** | 해당 칸 지면 스택과 오브젝트 전체 2픽셀 떠오름 + 칸 외곽 1픽셀 `#F2B33D` 윤곽 + 반짝 십자 픽셀 4~6 (색 + 움직임 이중 표시, 색약 대응) |

모든 앰비언트는 장식이며 게임 결과에 영향 없음.

## 11. 디오라마 연출 (화면 해상도 후처리)

순서: 버퍼 렌더 → 정수 확대 → 아래 후처리를 **화면 해상도**에서 (픽셀 버퍼에 블러를 걸면 뭉개진 블록이 된다).

1. **탁자:** 화면 해상도 원목 판재 3~4장(세로), 결 무늬, 판 틈 1px, 좌상단 광원 대각 그라데이션. 버퍼 밖이라 픽셀화하지 않음 → 탁자(실물)와 섬(장난감 픽셀) 대비.
2. **보드 림:** 바다를 감싸는 둥근 모서리 나무 테두리, 두께 14px·k, 윗면 하이라이트 + 안쪽 그림자, 탁자 위 드롭 그림자(오프셋 8, blur 10, α 0.35). 림과 바다는 버퍼 안(픽셀)으로 그려도 되고 밖이어도 됨 — **권장: 버퍼 안**(섬과 같은 픽셀 언어).
3. **틸트시프트:** 화면 위 18% / 아래 12% 띠만 별도 캔버스에 `filter: blur(2.5·k px)` 로 다시 그려 세로 그라데이션 마스크로 합성. 위쪽이 더 흐림. 블러 띠 채도 −10%.
4. **비네트:** 방사형, 중심 투명 → 가장자리 `#2A1A10` α 0.28, 시작 반경 = 대각선 × 0.62 (섬 위에는 거의 안 걸리게).
5. **오브젝트 그림자 (버퍼 안):** 모델별 바닥 실루엣(전 단면 합집합 마스크)을 광원 반대로 높이 × 0.3 픽셀 밀어 지면에 그림. 픽셀 단위, **그림자 전용 레이어에 마스크로 모은 뒤 한 번에** 지면을 한 단계 어두운 램프 색으로 치환(곱셈 겹침 없음 → 깔끔한 픽셀). 숲 내부는 거리장으로 이미 어두움.

## 12. 카메라 프레이밍 — "작고 답답함" 해결

- **섬(해변 포함) 바운딩 박스가 플레이 영역 가로 88% 또는 세로 82% 중 먼저 닿는 쪽**을 채운다 — §1.1 의 k 와 버퍼 크기로. yaw 회전 시 바운딩은 섬 외접원 기준(회전해도 잘리지 않음).
- 섬 둘레 바다 최소 1.2칸 폭(해변·거품·배가 보일 공간), 그 바깥이 림, 그 바깥이 탁자.
- 측면 고정 패널 폐지 → **보드 위 플로팅 카드** (폭 200px, 크림 α 0.94), 접으면 칩 1줄. 손패 카드 높이 90px, 보드 하단과 겹쳐도 됨.
- 줌 단계 = 정수 k ± 1 (Ctrl+휠/핀치). 비정수 줌 금지.
- 섬 칸 수 증가는 game-designer/사용자 결정 — 이 스펙은 프레이밍과 R=22 스케일로 해결.

## 13. UI 룩 — 미니멀 보드게임 칩

- UI 는 **화면 해상도 벡터**(한글 가독성). 픽셀 폰트 쓰지 않음.
- 연결고리: **자원 아이콘 = 실제 복셀 모델 썸네일** (밀 다발, 사람, 통나무, 양, 물고기 — 같은 굽기 파이프라인으로 yaw 45° 1장 렌더, 정수 확대). UI 와 섬이 같은 물건을 말한다.
- 상단 바 → 둥근 칩(높이 30, r 15, 크림 `#FBF3E2`, 테두리 `#C9A979` 1.5px, 그림자 0,2). 바 배경 없음.
- 자원 트랙: 막대 대신 원형 토큰 5개 채움.
- 보드 위 수치 라벨(+6 물고기): 흰 알약 + 모델 아이콘, 톡 튀어오른 뒤 1.2초 후 위로 사라짐.
- 배치 미리보기 유령: 모델 단면을 1픽셀 체커 디더(50%)로 그림 — 알파 대신 디더(픽셀 언어 유지) + 칸 외곽 흰 점선.
- 본문 `#4A3524`, 강조 `#F2B33D`, 경고 `#D9634A`, 최소 글자 12px.

## 14. 성능 계획

### 14.1 굽기 (로드 시)
- 모델 변주 수 목표 ≤ 80 (나무 ~30, 소품 ~30, 건물·동물 ~20). 생성 + 음영 굽기 → `(variant, rot8)` 별 단면 이미지 배열 (H 장의 작은 캔버스, 또는 **한 장의 가로 스트립 아틀라스**에 H 칸).

### 14.2 프레임 렌더 — 권장: yaw 스텝별 합성 캐시
- 카메라 yaw 를 **64스텝(5.625°)** 으로 양자화. 회전 드래그·Q/E 도 스텝 단위로 넘어감 (픽셀 아트에서 연속 회전은 지글거림이 심해 오히려 손해).
- 키 `(variant, rot8, yawStep, swayFrame)` → **완성된 스택 합성 이미지 1장** (모든 단면을 회전·압축·1px 오프셋으로 쌓아 놓은 것). LRU 캐시, 한도 64MB. 평균 합성 크기 ~20×30px → 2.4KB, 80변주 × 64 × 4 sway 최대 ≈ 49MB, 실제로는 방문한 yaw 만 굽혀 훨씬 작음.
- 프레임당 그리기: 지면 스택 10 + 바다 1 + 오브젝트 합성 이미지 N 회 + 이동체 + 오버레이.
- 예산 (100칸): 숲·마을이 많은 후반 칸당 평균 오브젝트 ~10 → **~1,000 drawImage/프레임** (합성 이미지라 단면 수와 무관). 데스크톱 브라우저 60fps 충분, 모바일 브라우저 30fps 목표.
- 대안(비권장): 매 프레임 단면을 회전해 그리기 = 1,000 오브젝트 × 평균 12 단면 = 12,000 drawImage → 회전 중에만 허용 가능한 수준, 정지 화면 상시로는 과함.
- 회전 중 캐시 미스: 해당 yaw 스텝의 합성을 그 프레임에 즉시 굽기 (모델 80개 × 12단면 ≈ 1,000 draw, 1회). 회전 스텝 사이 120ms 이징으로 굽기 시간 은폐.

### 14.3 정렬·무효화
- 깊이 정렬: 회전 후 버퍼 y (바닥 중심) 기준 전체 오브젝트 1회 정렬. 칸 단위 정렬 금지 (브리지 나무가 칸 경계를 넘음). 정렬 결과는 yaw 스텝·배치 변경 시에만 재계산.
- 칸 상태 변경 → 그 칸 + 이웃 6칸의 인스턴스 재생성, 지면 스택 해당 영역 재굽기, 숲 거리장은 그 무리 바운딩 박스만 재계산.
- 그림자 레이어: 오브젝트 그림자 마스크도 yaw 스텝별 1장으로 굽고 배치 변경 시 무효화.

## 16. 열린 질문 (사용자/디자이너 결정)

1. 성장 단계 임계값(1~2 / 3~5 / 6+)이 실제 무리 크기 분포와 맞는가 — game-designer 확인.
2. 미배치 칸 = "야생 들판"(채도↓, 1단 낮음) 해석이 맞는가, 아니면 미배치 칸은 바다/빈 슬롯인가.
3. yaw 64스텝 양자화(픽셀 선명) vs 연속 회전(부드러움, 지글거림) — 권장은 64스텝.
4. 계절 표현(가을 단풍 램프 등)을 넣을지 — 숲 색 식별성이 떨어지므로 넣는다면 실루엣으로 보완.
5. Godot 본 구현 시 이 파이프라인(복셀 → 단면 → 합성 캐시)을 그대로 옮길지는 technical-artist 검토 필요 (이 문서는 HTML 프로토타입 기준).
